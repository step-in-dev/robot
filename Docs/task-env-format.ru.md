# Формат файлов заданий `.env` для Робота

Файлы заданий имеют расширение `.env`, но их содержимое — JSON в кодировке UTF-8.

## Расположение файлов

Загрузчик ищет файлы заданий в таком порядке:

1. Каталог из переменной окружения `ROBOT_TASKS_DIR`.
2. Встроенный каталог `robot/tasks` внутри проекта.

Идентификатор задания можно передавать с суффиксом `.env` или без него. Он должен точно совпадать с именем файла без расширения (включая пробелы и знаки препинания). О группировке и навигации в просмотрщике см. [task-viewer.md](task-viewer.md#task-catalog).

## Структура верхнего уровня

Каждый файл задания должен содержать JSON-объект со следующими полями:

- `envDtos` (обязательное): массив описаний обстановок. Задание недействительно, если поле отсутствует, не является массивом или даёт пустой список обстановок.
- `todoText` (необязательное): условие задания, показываемое в интерфейсе.

Необязательные поля ограничений на решение (`operatorsLimit`, `customFunctionCallCount`, `ifLimit`, `whileLimit`, `requiredKeywords`, `bannedKeywords`) — см. [Ограничения на решение](#ограничения-на-решение).

## `todoText`

`todoText` поддерживает две формы:

- Простая строка, например `"Дойди до цели"`.
- Локализованный объект, ключи которого — **коды языка интерфейса** из `SUPPORTED_LANGUAGES` в [`robot/i18n.py`](../robot/i18n.py) (например `en`, `ru`, `zh-hans`, `ar`, `ur`, …). Пример: `{ "en": "Reach the goal", "ru": "Дойди до цели" }`.

При использовании локализованного объекта загрузчик:

1. Нормализует ключи языка, например `ru_RU.UTF-8` → `ru`.
2. Пробует текущий язык интерфейса.
3. Откатывается к `en`.
4. Использует пустую строку, если подходящее значение не найдено.

Нестроковые значения внутри объекта локализации игнорируются.

Для строк на **арабском** (`ar`) и **урду** (`ur`) применяйте те же правила Unicode bidirectional isolation, что и для остальных строк интерфейса: оборачивайте встроенные фрагменты слева направо (токены Python вроде `"for"`, `paint()`, латинские идентификаторы и западные цифры) символами U+2066 LRI … U+2069 PDI, как описано в [`localization-style.md`](localization-style.md#unicode-bidirectional-isolation-rtl-locales).

## Ограничения на решение

Необязательные поля верхнего уровня, которые накладывают ограничения на решение ученика на Python. Все они проверяются **статическим** анализом исходного кода (разбор AST или токенизация Python, без трассировки во время выполнения).

Поддерживаемые поля:

- `operatorsLimit` (необязательное): неотрицательное целое — лимит числа команд-действий Робота и вызовов своих функций в решении ученика.
- `customFunctionCallCount` (необязательное): неотрицательное целое — требуемое число подходящих вызовов своих функций.
- `ifLimit` (необязательное): неотрицательное целое — лимит того, сколько раз ключевое слово Python `if` может встретиться в решении как самостоятельный токен.
- `whileLimit` (необязательное): неотрицательное целое — лимит того, сколько раз ключевое слово Python `while` может встретиться в решении как самостоятельный токен.
- `requiredKeywords` (необязательное): список ключевых слов Python через запятую; каждое из них должно встретиться в решении как ключевое слово Python.
- `bannedKeywords` (необязательное): список ключевых слов Python через запятую; ни одно из них не должно встретиться в решении как ключевое слово Python.

### Когда выполняются проверки

Интерфейс вызывает эти проверки в [`robot/gui.py`](../robot/gui.py) **после успешного запуска**: когда **Выполнить** успешно проходит все обстановки или сеанс **Шаг** завершается успешно. [`run_solution_on_env`](../robot/executor.py) их не выполняет. Если программа завершается с ошибкой, падает или оставляет неверное конечное состояние, о нарушениях ограничений не сообщается.

### `customFunctionCallCount`

Вызов засчитывается только если выполняются все условия:

1. Вызывается своя функция верхнего уровня из того же решения.
2. До этой функции можно добраться из кода уровня модуля — по тем же правилам AST, которые применяет проверяющий код.
3. Тело функции содержит команды Робота: `move_right()`, `move_left()`, `move_up()`, `move_down()`, `paint()` или `printn()`.
4. Сам засчитываемый вызов находится вне вложенных областей, которые проверяющий код игнорирует, например вложенных `def`, `class` или `lambda`.

Примеры:

- `customFunctionCallCount: 2` выполняется, если одна своя функция вызвана дважды.
- `customFunctionCallCount: 2` также выполняется, если две разные подходящие свои функции вызваны по одному разу.

### `operatorsLimit`

Проверяющий код разбирает AST и считает:

1. Прямые вызовы команд-действий Робота: `move_right()`, `move_left()`, `move_up()`, `move_down()`, `paint()`, `printn()`.
2. Любые вызовы своих функций (`def` или `async def`), объявленных в том же исходном файле, независимо от уровня вложенности. В том числе:
   - вызовы из кода уровня модуля;
   - вызовы внутри других своих функций;
   - рекурсивные самовызовы.

Встроенные вызовы вроде `task()`, `field()`, `range()`, `len()` и т. п. **не** считаются, если только ученик сам не объявил функцию с таким же именем.

Пример:

```python
def step():
    move_right()
step()
step()
```

Здесь засчитывается 3: `move_right` (1) + `step` (2).

### `ifLimit` и `whileLimit`

- Значение должно быть неотрицательным целым.
- Проверяющий код использует токенизацию Python, поэтому ключевые слова внутри комментариев или строковых литералов не считаются.
- Каждое вхождение ключевого слова как самостоятельного токена учитывается, в том числе `if` в условном выражении вида `x if cond else y`.

Примеры:

- `ifLimit: 1` допускает один оператор `if` или одно тернарное `if`, но отклоняет два отдельных токена `if`.
- `whileLimit: 0` отклоняет любое решение с `while`.

### `requiredKeywords` и `bannedKeywords`

- Формат значения — строка со списком через запятую, например `"for,def"` или `"while, if"`.
- Пробелы вокруг элементов игнорируются.
- Пустые элементы игнорируются.
- Каждый элемент должен совпадать с ключевым словом Python, поддерживаемым текущей версией Python.
- Учитываются только жёсткие ключевые слова Python. Мягкие ключевые слова вроде `match` и `case` загрузчик намеренно отклоняет — при проверке исходного кода они не учитываются.
- Проверяющий код использует токенизацию Python, поэтому ключевые слова внутри комментариев или строковых литералов не считаются.

Если одно и то же ключевое слово указано и в `requiredKeywords`, и в `bannedKeywords`, загрузка задания завершается ошибкой.

Примеры:

- `requiredKeywords: "for,def"` требует, чтобы в решении были и `for`, и `def`.
- `bannedKeywords: "while"` отклоняет любое решение с `while`.
- `requiredKeywords: "for"` выполняется для `for _ in range(3): ...`, но не для комментария вроде `# for`.

## Формат элемента `envDtos`

Каждый элемент в `envDtos` должен быть объектом с обязательными полями:

- `width`: ширина поля.
- `height`: высота поля.
- `startRow`: начальная строка Робота.
- `startCol`: начальный столбец Робота.
- `finalRow`: целевая строка.
- `finalCol`: целевой столбец.

Поддерживаемые необязательные поля:

- `walls`: массив отрезков стен.
- `paintedCells`: массив уже закрашенных клеток в начале.
- `cellsToPaint`: массив клеток, которые решение должно закрасить.
- `pollutedCells`: массив клеток со значениями, которые читаются через `pol()`.
- `cellsToPrint`: массив клеток со значениями, которые нужно вывести через `printn()`.

### Форматы клеток

Простой объект клетки:

```json
{ "r": 1, "c": 3 }
```

Клетка со значением:

```json
{ "r": 1, "c": 4, "value": 7 }
```

Отрезок стены:

```json
[
  { "r": 0, "c": 0 },
  { "r": 0, "c": 1 }
]
```

`walls` должен описывать преграду между двумя соседними клетками.

## Минимальный пример

```json
{
  "envDtos": [
    {
      "width": 5,
      "height": 1,
      "startRow": 0,
      "startCol": 0,
      "finalRow": 0,
      "finalCol": 4
    }
  ],
  "todoText": "Дойди до конца"
}
```

## Расширенный пример

```json
{
  "envDtos": [
    {
      "width": 7,
      "height": 5,
      "startRow": 0,
      "startCol": 0,
      "finalRow": 4,
      "finalCol": 6,
      "walls": [
        [
          { "r": 0, "c": 1 },
          { "r": 0, "c": 2 }
        ]
      ],
      "paintedCells": [
        { "r": 1, "c": 2 }
      ],
      "cellsToPaint": [
        { "r": 1, "c": 3 }
      ],
      "pollutedCells": [
        { "r": 1, "c": 4, "value": 1 }
      ],
      "cellsToPrint": [
        { "r": 1, "c": 5, "value": 1 }
      ]
    }
  ],
  "todoText": {
    "en": "Paint and print required cells",
    "ru": "Закрась и выведи нужные клетки"
  },
  "operatorsLimit": 10,
  "customFunctionCallCount": 1,
  "ifLimit": 2,
  "whileLimit": 0,
  "requiredKeywords": "for,def",
  "bannedKeywords": "while"
}
```
